## 四、落档与结论纪律

- **两层分开**：原样存档（带来源头＝站点 / URL / 采集日期 / 抓取通道 / 社区整理提示）＋ 整理档（提炼）。整理档引用时指向存档
- 来源强度：官方 / 游戏内文本 ＞ 官方站 / 百科 ＞ 社区 wiki。wiki 结论落进正式档前交叉验证，查不到标「待核」
- **先穷尽、再下结论**：换过通道、试过词条名变体、翻过总条目之后，才允许写「无证据」
- **批量归档：先落映射表，再逐档填肉**。抓下几百条后不要直接写正文——先产出 `条目 → 目标档案` 的逐条映射表（codexId｜条目名｜去向），一条不落；映射表本身就是交付物：能对账（条目数＝映射行数）、能查（后续问「这条为什么归这个档」）、能接脚本（按映射批量生成骨架）。没有映射就开写，必然漏条且无法验收。
- **骨架档生成器三条铁律**：只抄原文（背景故事／记忆花瓣／书页内容），不重写不脑补；档头标明「骨架·待补」；**已存在的档一律跳过，绝不覆盖**——人工精写过的内容一旦被自动生成冲掉，损失不可见。精写与骨架在索引里用不同状态标记区分。
- **一条目多形态 → 合并成正式档＋指针档**：同一对象在不同条目里换名字（本名／称号／形态／化名）是常态，先按本名合并成一个正式档，其余名字写成三行指针档（指向目标＋合并理由）；内容分摊到两档必分叉。
- 抓回来的缓存要去重（同一页可能有多个 hash 副本），保留最长版本；文件名是 hash，**靠正文里的 URL/标题行识别页面，别按文件名猜**。部分缓存件**根本没有可用的标题行**（回显被截断过／站点结构不同），此时按**正文首段的内容签名**认页（人物页认全名、作品页认英文名，写一张 `特征词→页名` 的小表），认不出来就按长度与已抓清单对照后手工命名——别让它落成无名件，更别让多份无名件**互相覆盖**（同名写入会静默吃掉先前那份，归档件数与抓取数对不上就是这里丢的）

### 机制拆解档的骨架（拆一个站点／产品的功能时照这套摆）

| 文件 | 装什么 | 硬要求 |
|:--|:--|:--|
| 「README.md」 | 一句话说明这是什么产品、触发、落档判据、文件导航、硬事实清单、缺口 | 不读正文也知道拿到了什么、没拿到什么 |
| `01-结构与路由` | 技术栈、路由表、robots 的 Disallow 清单、sitemap、状态实测、chunk 地图 | 别人能照着再抓一遍 |
| `02-数据全量` | 题库/清单原始 JSON ＋ 可读表格 | 原件进 `原件/`，正文里只放表与指针 |
| `03-算法与编码` | 公式、常量、位格式，附可重算步骤 | **闭合才算「已复现」**；没闭合就写「未复现／推断」 |
| `04-文案全量` | 逐条/逐型文案，原文一字不改 | 这类是素材，不摘要不重写 |
| `05-结果与变现` | 实跑样本、免费/付费分界、价格、钩子话术 | 免费与付费分开写；样本要真跑 |
| `06-脚本与缺口` | 可重跑脚本＋环境要求＋缺口表 | **缺口单独成表**，写「没拿到」而不是省略 |
| `原件/` `scripts/` | HTML、JSON、localStorage、可重跑脚本 | 原件带抓取时间；脚本逐个实跑过 |

三条纪律：**算法读到就复现一遍**（同一公式重算必须得同一结果，闭合了才写已复现）；**缺口不隐藏**（写成表，比写成正文里的“未及”明确得多）；**实跑样本必须真跑**（编的样本会把整档带偏）。

### 测验页再往前一步：扒完还要判它准不准

「你的XX角色是」「几道题测出你是什么人」这类页，扒出题库和算法只算做了一半——**交付的结论要落在「信不信得过」上**，不是复述它给了什么结果。三个判据按杀伤力排：

1. **百分比函数的签名**：`function pct(rank)` 只吃名次、不吃用户向量 ⇒ 百分比是名次化妆（第一名恒 93%、末位恒 65% 这类曲线，换谁做都一样）。先打开函数体看首尾两个常数，再谈准不准。
2. **分辨率**：随机答卷 ＋ 改 1/3/5 题扰动，看第一名换人的概率。改一题就换人探到三成以上，等于单题噪声大过向量间距——这种测试测的是「有没有点完」，不是性格。
3. **覆盖与垄断**：每维题目数/总权重（最薄那维≈随机抽）、角色向量唯一数（撞车）、随机答卷的头部集中度（少数角色吸走大量第一，多为角色向量均值偏正＋用户向量向中心收所致）。
