# 娱乐测验页复核（「你的XX角色是」这类）

> 用途：群里／朋友甩来一个测试链接，要在一轮对话里答出两件事——**它收不收数据**、**它准不准**。
> 工具：`scripts/quiz_audit.js`（一条命令出全部指标）。本档只放判据与尺子。

## 一、安全面（先做，最快）

```bash
curl -sS -m 20 -A "Mozilla/5.0 (Linux; Android 13) AppleWebKit/537.36 Chrome/126 Mobile Safari/537.36" \
  -D hdr.txt -o page.html "<url>"
```

- `server:` 头认托管方（CloudStudio / Vercel / Netlify 一类＝静态托管；**随机子域名＝临时部署**，别指望它有任何隐私政策与运营主体）
- 扫外发通道：`fetch(`／`XMLHttpRequest`／`sendBeacon`／`document.cookie`／`localStorage`／`new Image`／统计脚本名
- **全 0 ⇒ 纯本地算分，一个字都没外发**（仍然别填手机号、别授权登录；页面没有输入框就更好）
- **有命中 ≠ 偷数据**：先读那段请求代码，看 payload 收了什么再定性；CSS 里的 `url()` 不算外发

## 二、数据面：用 node 求值，别用正则抠数组

题库和角色表常以 `window.X = [...]` 内嵌在 `<script>` 里，形状还带中文引号、嵌套数组、渐变字符串：

```js
const blocks = [...html.matchAll(/<script[^>]*>([\s\S]*?)<\/script>/g)].map(m => m[1]);
const dataCode = blocks.filter(b => /window\.\w+\s*=/.test(b) && !/document\./.test(b)).join('\n');
const sandbox = {};
new Function('window', dataCode)(sandbox);   // 沙箱求值，不污染宿主
```

- **括号平衡扫描也栽**：数组元素里有字面量括号、引号里的标点，扫到一半就断；求值一次拿到的就是真结构
- 求值后**按形状认对象**，别按变量名猜：带 `.o`（选项数组、每个选项有 `.s` 权重表）的是题目，带数值数组 `.v` 的是角色/结果向量
- 数据不在页面里（走接口或 SSR JSON）→ 换 `python3 scripts/siteprobe.py --dump` / `references/nextjs-app-router.md`

## 三、三个判据（按杀伤力排）

**1）百分比函数的签名 —— 决定「%」这个数字有没有意义**

找到生成百分比的函数（常叫 `pct`／`percent`），只看它**吃什么**：

```js
function pct(rank) { /* 只吃名次，不碰用户向量 */ }
```

只吃名次 ⇒ 百分比是排名的化妆，与答案无关。把函数体抄出来套 `new Function('N','return '+src)(N)` 求 `pct(0..5)` 与 `pct(N-1)`，首尾两个常数就是它写死的天花板与地板。**先做这一条**：命中了，后面所有「重合度 9X%」都不必当真。

**2）分辨率 —— 决定「换个答案结果会不会变」**

随机生成答卷 → 随机改 1／3／5 题 → 统计第一名换人的比例（每档至少 40 份 × 200 次扰动）。改一题就大面积换人＝单题噪声大于向量间距。

**3）覆盖与垄断 —— 决定「题目范围能不能保证」**

- 每维题目数 × 总权重：找最薄的一维（题少且单题封顶低的那维，结果≈随机）
- 每题涉及的维度数：一题同时打 6~9 维＝全场纠缠，单题信息被摊薄，不是「一题探一维」
- 角色向量唯一数：判有没有撞车（全唯一＝作者的锅不在撞车，在分辨率）
- 随机答卷的头部集中度 HHI＝Σ(占比²)，均匀分布时 = 1/N；远高于 1/N 就是少数角色垄断

### 判读尺子（N＝角色数）

| 指标 | 结实 | 只能当娱乐 | 别拿它看人 |
|:--|:--|:--|:--|
| 改 1 题后第一名换人概率 | <10% | 10–30% | >30% |
| 单维题目数 | ≥25 且十维均衡 | 有一两维偏薄 | 某维 <20 且权重垫底 |
| HHI ÷ (1/N) | <3 | 3–10 | >10 |

## 四、结论怎么写

- **顺序：先安全，后准确，最后一句定性。** 先说「有没有外发、要不要防」，再说「算法是怎么算的」，最后给「当娱乐可以，别拿它量人」这类可执行判词
- **不评价角色本身好不好看／适不适合**——那不是测试的事；对方问「准不准」，答的是算法分辨率，不是替人做性格诊断
- 群聊场景按群规：短、纯文本、只给结论；完整拆解等追问或转私聊
- 想要数值就用数值说：「改一题三成概率换人」比「不太准」有说服力

## 五、踩坑

- **别先夸「93% 好高」再看算法**：那个数很可能与答案无关，先把 pct 函数翻开
- **头部垄断别读成「算法偏爱你」**：角色向量均值偏正（坚韧/果决/利他这类普遍给高分）＋ 用户向量 z 化后向中心收，两头挤在中间，谁离中心近谁赢
- **向量两两不重复 ≠ 结论可靠**：唯一性只排除了「撞车」，排除不了「分辨率低」
- **别把这类页当心理学量表**：40 题 × 4 选项的信息量撑不起十维建模，写成「娱乐向、方向大致对」已是上限
- 结论里不写「我复现了算法」的内务流水，直接给判据和数字
